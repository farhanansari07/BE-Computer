Q. Write a smart contract on a test network, for Bank account of a customer for following 
operations: 
• Deposit money  
• Withdraw Money 
• Show balance

-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
Code
-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.0;

contract Bank {
    address private accOwner;
    uint256 balance = 0;

    constructor() {
        accOwner = msg.sender;
    }

    function Deposit() public payable {
        require(accOwner == msg.sender, "You are not an account owner!");
        require(msg.value > 0, "Amount should be greater than 0.");

        balance += msg.value;
    }

    function Withdraw(uint256 amount) public {
    require(accOwner == msg.sender, "You are not an account owner!");
    require(amount > 0, "Amount must be greater than 0.");
    require(amount <= balance, "Insufficient balance!");

    balance -= amount;

    (bool success, ) = payable(msg.sender).call{value: amount}("");
    require(success, "ETH transfer failed!");
    }

    function showBalance() public view returns (uint256) {
        require(accOwner == msg.sender, "You are not an account owner!");
        return balance;
    }
}

1. Aim
To write and deploy a smart contract on an Ethereum test network using Solidity to perform banking operations such as depositing money, withdrawing money, and checking the account balance.

2. Theory
A Smart Contract is a self-executing program stored on a blockchain that automatically executes predefined instructions when specified conditions are satisfied.
Solidity is a high-level programming language used to develop smart contracts on the Ethereum blockchain.
In this practical, a smart contract named Bank is created to perform basic banking operations.

The contract contains the following operations:
1. Deposit Money: Allows the account owner to deposit Ether into the smart contract. The deposited amount is added to the account balance.
2. Withdraw Money: Allows the account owner to withdraw Ether from the contract, provided sufficient balance is available.
3. Show Balance: Displays the current balance of the account owner.
The contract uses msg.sender to identify the person calling the function and msg.value to identify the amount of Ether sent with a transaction.

The require() statement is used to validate conditions and prevent unauthorized access or invalid transactions.

The smart contract stores the owner's address and balance on the blockchain, providing transparency, security and reliability.

3. Algorithm
Step 1: Start.

Step 2: Declare a smart contract named Bank.

Step 3: Declare variables to store the account owner's address and account balance.

Step 4: Initialize the account owner's address using msg.sender in the constructor.

Step 5: Create a Deposit() function:
- Check whether the caller is the account owner.
- Check whether the deposited amount is greater than zero.
- Add the deposited amount to the account balance.
Step 6: Create a Withdraw() function:
- Check whether the caller is the account owner.
- Check whether the withdrawal amount is greater than zero.
- Check whether sufficient balance is available.
- Deduct the amount from the balance.
- Transfer Ether to the account owner.
Step 7: Create a showBalance() function:
- Verify the account owner's address.
- Return the current account balance.
Step 8: Deploy the smart contract on an Ethereum test network.

Step 9: Perform deposit, withdrawal and balance-checking operations.

Step 10: Stop.


Overall time complexity: O(1) for each operation.

Note: This is the algorithmic time complexity. Actual blockchain transaction cost is measured in gas and depends on the operations performed.
